# Safe terminal rendering

Public text rendering is safe by default. Terminal controls and displayed text use separate output operations and are validated again at the final sink.

## Default policy

`Text`, layout helpers, syntax-highlighted source, renderer patches and direct terminal-sink writes are checked before terminal bytes are emitted.

The default policy is equivalent to:

```js
createTerminalPolicy({
  mode: 'safe',
  hyperlinks: 'disabled',
  blockedControlRendering: 'visible',
})
```

Safe rendering:

- preserves printable Unicode;
- normalizes CRLF and CR to `\n`;
- preserves tabs and line breaks;
- permits validated SGR styling used by Terlio themes and components;
- blocks CSI cursor movement, erase, mode changes, queries and terminal replies in text;
- blocks OSC, DCS, APC, PM, SOS and C1 controls in text;
- validates terminal controls generated by the renderer and runtime at the final sink;
- makes blocked controls visible by default, for example `ESC [ 2 J` is rendered using a visible escape symbol rather than executed.

Validated SGR in ordinary `Text` is a compatibility allowance: it can change the presentation of that text, but it cannot move the cursor, erase content, switch terminal modes, write the clipboard or emit other control families. Applications that require untrusted content to have no styling influence should strip ANSI before creating the node. The explicitly unsafe `unsafeRawAnsi()` wrapper is stricter in safe mode and does not preserve even valid SGR.

Use `blockedControlRendering: 'remove'` to remove blocked controls while preserving surrounding text:

```js
renderToString(Text(untrusted), {
  width: 80,
  height: 4,
  terminalPolicy: createTerminalPolicy({
    blockedControlRendering: 'remove',
  }),
})
```

## Structured styling

Built-in themes and syntax highlighting continue to use SGR colors and attributes. Theme values are accepted only when the complete value consists of supported SGR sequences. Cursor movement, erase operations, private modes, OSC and arbitrary text are rejected as style tokens.

This keeps existing Terlio styling compatible without allowing a custom theme token to become a general terminal-control channel.

## Trusted mode

Applications that intentionally render terminal-specific ANSI may select trusted mode:

```js
renderToString(node, {
  width: 80,
  height: 24,
  terminalPolicy: 'trusted',
})
```

Trusted mode bypasses Terlio's terminal-injection filtering for rendered text. Do not use it for LLM output, logs, filenames, pasted text, tool output, session content or other untrusted values.

A deliberately named marker is available when raw output should be visually explicit in source code:

```js
import { Text, unsafeRawAnsi } from 'terlio.js';

const node = Text(unsafeRawAnsi('\x1b[2J'));
```

`unsafeRawAnsi()` does not bypass safe mode by itself. Raw bytes are emitted only when the surrounding renderer also uses the explicit `trusted` policy.

## Hyperlinks

Structured hyperlinks are disabled by default. The internal terminal-output model can enable them only through a policy with an explicit URI-scheme allowlist. Labels and targets are sanitized, controls are rejected, and byte limits are applied before an OSC 8 sequence is produced.

## Final sink enforcement

Component-level sanitization is not the only boundary. `TerminalRenderer` routes patches through the terminal sink, which validates mixed renderer controls and frame text again. A custom frame or component that accidentally contains OSC, DCS or unsupported CSI therefore cannot bypass the default protection.
